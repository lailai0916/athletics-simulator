## 常用命令

使用 Node.js 22 或更高版本，通过 `npm ci` 安装锁定的开发依赖。

| 命令                   | 用途                                                          |
| ---------------------- | ------------------------------------------------------------- |
| `npm run dev`          | 在 `http://127.0.0.1:5173` 提供内存构建；修改源码后刷新页面。 |
| `npm run build`        | 将应用组装为 `dist/index.html`。                              |
| `npm run preview`      | 在 `http://127.0.0.1:4173` 提供已有构建产物。                 |
| `npm test`             | 运行可移植的 Node 回归测试。                                  |
| `npm run format`       | 应用 Prettier 格式。                                          |
| `npm run format:check` | 检查格式，不修改文件。                                        |
| `npm run check`        | 运行格式检查、回归测试与构建。                                |

需要其他端口时，可使用 `npm run dev -- --port 5174` 或 `npm run preview -- --port 4174`。服务器默认绑定 `127.0.0.1`。构建后的 HTML 不依赖网络，也可以作为本地文件打开。

运行时使用浏览器原生 HTML、CSS、SVG 和 JavaScript。Prettier 属于开发依赖；构建后的应用运行时不需要 npm。

## 源码与构建结构

源码采用片段集成为单页的方式，没有运行时模块加载器。`scripts/assemble.cjs` 维护唯一片段清单，并向构建与测试提供 `assembleApp()` 和 `assemblePage()`。新增片段只在这里登记，不要在测试或服务器中另建一份清单。

`src/index.html` 维护页面外壳、控件、SVG 定义与图层顺序，源码占位符由组装器替换。`src/track-app.js` 管理应用状态，集成几何、视角、渲染与控件。源码片段为共享所在作用域的 JavaScript，并非全部都是独立 ES 模块；函数顺序及初始化依赖需要保持一致。

| 源码                                                          | 职责                                         |
| ------------------------------------------------------------- | -------------------------------------------- |
| `track-data.js`                                               | 项目元数据、尺寸、配色及参考链接。           |
| `marking-precision.js`                                        | 实体标线几何、道线、起点、抢道线与接力标记。 |
| `steeple-precision.js`、`steeple-kerb-fragment.js`            | 水池路线与对应内突沿开口。                   |
| `measured-motion.js`、`course-motion.js`                      | 路径弧长测量、路线连接与比赛进度转换。       |
| `race-motion.js`                                              | 具有积分起步及冲线减速段的统一比赛时钟。     |
| `merge-motion.js`                                             | 平滑抢道与集团路线过渡。                     |
| `relay-motion.js`、`relay-render.js`                          | 接力棒次状态、连续交接运动及运动员表现。     |
| `camera-controller.js`                                        | 合并平移/缩放请求与屏幕到场地的坐标转换。    |
| `event-picker.js`、`event-picker.css`                         | 支持键盘操作的项目选择。                     |
| `label-layout.js`                                             | 文字度量与几何居中。                         |
| `football-pitch.js`、`football-goals.js`、`static-surface.js` | 足球场、球门与随视野变化的表面细节。         |
| `route-trace.js`                                              | 渲染使用的有误差上限的路线采样。             |

分发文件为 `dist/index.html`。修改 `src/` 后重新构建、检查结果，不直接编辑产物。测试与构建必须组装同一份源码。测试启动标记仅用于让测试工具在不启动浏览器动画的情况下访问应用内部状态。

## 坐标与运动约定

- 场地几何使用米：未旋转的 SVG 世界中，x 向右、y 向下。标线宽度属于场地坐标，不得设置屏幕像素下限。
- 路线位置应提供有限的 `x`、`y`，并在调用者需要时提供切向方向。弧长测量将路线参数转换为实际平面行进距离；参数增加一并不自动证明行进了一米。
- 统一比赛时钟以模拟秒推进，巡航段为 10 米/秒。播放倍数改变时钟推进速度，不改变比赛距离、标线尺寸或路线几何。
- 起步、并道、接力及冲线后缓冲段均有连续性要求。检查连接点两侧的位置、速度与加速度；端点看似合理不能证明路径平滑。
- 视角坐标与比赛进度独立。切换项目、切换分组起跑与拖动进度必须保持约定的视角及选择行为；跟随时滚轮改变视野大小，拖动不得平移视角。
- 图层顺序对应指定标线图。永久标线应在切换项目时保留，避免重复描绘同一实体笔画，并根据引用图检查交叉关系；不能将一种全局颜色叠放顺序当成所有交点的规则。

浏览器内部全局对象 `TrackApp`、`TrackMath` 可用于检查。它们在 0.x 版本中属于实现细节，不是稳定的外部 API。新增扩展接口应先明确约定并建立回归覆盖，再列为正式支持的 API。

## 新增或修改项目

1. 确定所依据规则的版本、章节及具体赛制，在模型与参考文档的两个语言版本中记录，区分强制规则与所选演示行为。
2. 增加项目目录项及两种界面翻译，填写距离、路线类型、起跑方式、接力棒距或跨栏数据，以及该类型支持的前伸参数。
3. 只有当起跑、分道限制、抢道点、终点与交接行为一致时，才复用已有路线类型；否则明确实现新的几何与运动策略。
4. 将永久标线与当前选中项目分离，保留实体笔画宽度、前后边缘、虚线节奏、裁切及共享标记归属。
5. 验证路线长度、起点偏移、合法道内范围、抢道条件、交接区位置与共同终点对齐，覆盖支持的普通与分组起跑模式。
6. 检查起跑、切点、并道连接、交接、冲线及冲线后缓冲段，既按路线参数采样，也按真实经过时间采样。
7. 在真实浏览器中测试两种语言和键盘操作，评审证据应包含项目、播放位置与视角状态。

战术功能需要单独建立运动员能力、配速策略、合法超越、交互决策及验证数据；当前预设路线引擎没有提供这些内容。应将它们与实测设施几何、规则要求分开维护。

## 自动验证

提交修改前运行 `npm run check`。测试覆盖源码可验证的几何与运动不变量，并通过轻量 DOM、动画工具检查交互和渲染回归。新增测试应能发现有意义的错误，不要只重复实现逻辑。

构建检查应发现未替换的源码占位符，并产生用户实际运行的同一个自包含应用。持续集成还会从已审查的固定模板提交运行仓库规范检查；规范检查不能替代模拟测试。

模拟文字度量与 Node DOM 工具无法证明特定浏览器的字形排版、GPU 开销、事件顺序或渲染性能。断言数量再多，也不能代替对这些边界的检查。

## 浏览器验收

发布检查使用构建后的页面。修改 SVG 渲染、细节阈值或视角输入时，至少检查 Chromium 和 Safari。

- 在桌面、较矮横屏、较窄竖屏中完整显示横向操场，检查终点线、直道延伸及所有道线。
- 使用鼠标和键盘打开菜单，到达最后一个选项并选择，检查 Escape 与焦点返回；在窄屏中检查两种语言。
- 平移、深度放大、放大后拖动、调整窗口尺寸，检查静态纹理或细节是否引起持续卡顿或标线脱离。
- 选中运动员或队伍，播放、暂停、拖动进度、修改倍数、跟随时缩放并尝试拖动，检查文档约定的跟随与选择行为。
- 播放抢道前后及三次接力交接，既观察持棒运动员，也观察已完成的运动员是否连续。
- 高倍率检查起点、共享接力钩线、栏位短线、抢道线交叉、线宽、文字、球网及障碍赛内突沿开口。

记录浏览器及版本、视口、项目、分组状态、播放位置与观察结果，区分自动测试通过与人工视觉或性能检查结论。

## 变更与发布

使用 Conventional Commits 提交标题，例如 `fix(motion): preserve distance through the lane break`。修改面向用户的文字、模型假设、命令或文档行为时，同步两个语言版本。

项目采用语义化版本。在 0.x 开发阶段，将可观察行为及接口变更记录到 `CHANGELOG.md`，不要暗示扩展 API 已稳定。发布应标明精确提交，完成干净安装后的 `npm ci` 与 `npm run check`，并在真实浏览器检查构建页面。不要将官方规则 PDF 或下载的参考图作为项目许可素材分发，应链接原始来源。
